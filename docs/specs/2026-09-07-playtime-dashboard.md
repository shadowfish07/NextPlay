## 数据与运行边界

- 使用账户配置 timeZone 的自然日，当前日始终标记为尚未完整。
- 周期新增是已观测到的可靠间隔之和，含缺口时明确标注“已记录新增”。
- 累计值来自最近完整游戏库快照，不补画首次采集前的数据。
- SQL 按观测和自然日聚合；不沿用单游戏明细 1000 行截断；使用 account/observed 索引。
- 首版不推导精确启动/退出时间、游玩次数，也不加入成就/笔记时间线。
- Flutter 页面测试和 Android 导航使用显式 fixture 服务；公共服务读取验收另行进行，不将 fixture 数字当作个人历史。
- 读取失败保留错误页并提供“重新加载”；它只重试读取，不触发服务采集。

## 游玩日历扩展

用户要求增加 GitHub 风格的热力图。图表切换新增「游玩日历」，默认切到近 365 天；范围选择增加「一年」。日历以周为列、周一至周日为行，显示月份并支持横向滚动和日期明细。颜色档位为 0、1–29、30–59、60–119、至少 120 分钟；暂无数据为空心，不完整日期使用单独边框。游玩日数量只统计可靠间隔内的正增量，不推算连续打卡或精确会话。

生产组件为 `HistoryHeatmap`，复用既有账户授权、时间分桶和日期弹层；API 仅扩展合法范围 365。Host widget 覆盖切换年范围和点击日期，服务测试覆盖年范围授权读取；Android 另行检查日历布局、滚动与日期弹层。演示 fixture 为完整年度数据，生产不会生成或回填历史。

日历验收：50 个 Flutter 测试、36 个服务测试通过，Android 构建/安装/启动及日历点击、滚动通过；实际截图 `.artifacts/history-visual/history-calendar.png` 已检查。临时截图等待钩子未保留在固定测试中。

## PR #12 评审修正

- 历史上传按完整 JSON 的 UTF-8 字节数分批，限制为服务端的 1,000,000 字节；单条超限记录保留原始 outbox 内容及 `payload_too_large`，不假装确认，不阻塞后续事件。
- SQLite v7 为上传失败增加持久化字段。账号切换在事务中保留并恢复该账号的本地游戏状态、队列和 Steam 快照；baseline 按账号记录，v6 旧数据沿用原 baseline 账号归属。
- 摘要的“部分记录”表示真实缺口或不可靠数据；今天尚未结束仍在日期明细标记为不完整，但不会单独让所有期间摘要恒为部分记录。当天真实缺口仍会标记。
- 游戏逐日查询不再计算前一比较窗口；比较数值仍使用已结束日期的可靠观测。期间比较文案使用摘要背景配套的前景色。

修正验收：54 个 Flutter 测试、36 个服务测试通过，覆盖率 48.95%；账号切换与超限上传回归在原代码上失败，修正后通过。Android SQLite v6→v7、账号隔离、失败原文持久化及既有导航和独立 APK 安装/启动通过。实际 Android 深色摘要截图已检查，比较文案清晰；截图使用显式 fixture，并已移除临时采集钩子。编译后 HTTP 服务的 7/30/365/全部、真实缺口、账号隔离和单游戏契约使用隔离合成记录验证通过；公共服务 smoke 另行通过，本轮尚未部署后端修正到生产。

Codex 复审修正：期间比较取已结束日期之前相邻、等长的窗口，避免丢弃最近前一天而向前偏移。跨零点且上一条观测仍在 90 分钟正常间隔内时，今天的日期格仍显示暂无数据，但摘要不误报采集缺口；超过间隔后继续标记真实缺口。使用不均匀时长和跨零点夹逼用例证明两项原断言失败、修正后通过。

最后一轮性能修正：将逐日游戏 SQL 循环替换为日期边界 CTE 和一次索引连接聚合；小时明细保留在 SQLite 内计算，不扩大响应数据。365 天及全部历史的结果查询次数回归在旧实现检测到 366 次而失败，新实现固定为 2 次（采样聚合和游戏日期聚合），并保留账户时区与既有数据口径。

### 账号同步时间兼容性

同步完成时间使用 `last_sync_time:<Steam ID>` 保存，写入绑定发起同步的账号。启动时的一分钟去重判断和设置页通过 `GameRepository.lastSyncTime` 读取当前账号的时间。旧 `last_sync_time` 没有可靠账号归属，因此保留原值但不再读取或迁移到任意账号；升级后可能多执行一次自动同步，避免错误阻止新账号同步。切换账号、重启后读取、设置页展示和切回原账号均有回归覆盖。
